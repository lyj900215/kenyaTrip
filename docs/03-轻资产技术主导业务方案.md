## 1. 一句话定位

**"中非之间的 AI 旅行规划师"**：用户用中文（或英文/斯瓦希里语）说出想法，AI 在几十秒内给出可执行、已核价的行程，并一键完成机票、酒店/营地、用车（Safari 车/接送机）及签证材料的预订与准备。

- **A 线（中国 → 肯尼亚）**：主战场。解决的痛点是"信息少、规划难、报价不透明、怕被坑"。
- **B 线（肯尼亚 → 中国）**：次战场。解决的痛点是"签证材料复杂、不会用中国的支付/打车/订票、展会与采购行程难安排"。

## 2. 为什么要从重资产转向技术主导

| 维度 | V1 自营地接社 | V2 AI 平台（本方案） |
|---|---|---|
| 核心资产 | 人（计调、导游）、车辆、营地关系 | 行程知识图谱、规划算法、供应商连接、用户数据 |
| 扩张方式 | 线性加人 | 边际成本趋近于零，一套系统服务两条线和更多国家 |
| 收入确认 | 按团款总额，毛利率 12–18% | 按佣金/服务费净额，净收入率（Take rate）10–15%，毛利率 60%+ |
| 资金占用 | 营地订金、旺季预付，营运资金重 | 尽量由供应商或支付渠道作为收款方（MoR），平台不垫资 |
| 合规难点 | 中国出境组团资质 | 仍需处理，但可通过"组件代订 + 持牌社合作 + SaaS"结构化解决（见第 5 节） |
| 护城河 | 弱（易被价格战） | 本地供给数字化 + 实时动态数据 + AI 规划质量 + 双向网络效应 |

**关键判断**：全球机票、酒店已经可以通过 API 标准化接入；真正**没有被数字化**的是东非的"最后一公里"——Safari 用车、营地实时库存、中文导游、动物迁徙动态。谁把这部分数字化并接入 AI 规划，谁就拥有壁垒。

## 3. 产品组合

### 3.1 面向游客（C 端）
| 模块 | 说明 |
|---|---|
| **AI 路线推荐** | 根据月份（如大迁徙位置）、预算、天数、人群（亲子/摄影/老人）、偏好，推荐 2–3 条可行路线并解释理由 |
| **AI 行程规划** | 生成逐日行程（路程时长、公园开放时间、游猎时段、餐食、住宿），支持对话式修改（"第三天轻松一点""加一晚热气球"） |
| **一键预订** | 机票 + 酒店/营地 + 用车 + 门票 + 保险，一次付款，系统编排各供应商下单，失败自动替代或退款 |
| **出行准备** | 肯尼亚 eTA / 中国签证材料清单与填写辅助、疫苗与健康提醒、行李清单、货币与支付指南 |
| **行中伴游** | 行程提醒、司机与车辆信息、航班变动重排、紧急求助、实时翻译 |

### 3.2 面向供给方（B 端）
| 模块 | 说明 |
|---|---|
| **供应商门户**（肯尼亚 Safari 车队、营地、导游、中国入境地接） | 库存日历、价格规则、订单确认、结算；支持 WhatsApp 确认，降低本地中小供应商使用门槛 |
| **旅行社 SaaS**（国内组团社/定制师） | 把 AI 规划器白标给持牌旅行社使用：他们出报价单、签合同，平台负责规划和供应商下单 |

### 3.3 渠道形态
- 中国：**微信小程序**（主）+ H5（小红书/抖音引流落地页）+ 企业微信 AI 客服
- 肯尼亚：**Web/PWA** + **WhatsApp 对话式预订**（肯尼亚最主流的沟通工具）+ M-Pesa 支付

## 4. 商业模式

### 4.1 收入结构

| 收入项 | 模式 | 预期费率 |
|---|---|---|
| 机票 | 服务费（固定金额/票）或代理佣金 | US$10–25/票，或 1–3% |
| 酒店/营地（API 批发价） | 加价或佣金 | 10–18% |
| 肯尼亚本地用车/导游/活动（平台自有供给网络） | 加价/佣金 | **18–25%**（最高利润组件） |
| 动态打包溢价 | 组合价格不拆分展示 | 额外 3–5% |
| 签证/eTA 材料辅助服务 | 服务费 | US$15–40/人 |
| 保险 | 佣金 | 15–30% |
| 旅行社 SaaS | 年费 + 每单技术服务费 | ¥3,000–10,000/年 + 1–2% GMV |
| 会员/高级规划（可选） | 订阅或单次付费的人工定制师 | ¥99–499/次 |

**混合 Take rate 目标**：第 1 年 ≈ 11%，第 3 年 ≈ 14%（随本地供给占比上升）。

### 4.2 为什么 B 线在平台模式下更合理
在 V1 中，B 线体量小、难以支撑专门团队；在平台模式下，B 线只是**同一套系统换一个目的地知识库和供应商集合**：机票走同一 API，中国酒店走同一批发商，用车与地接接入中国入境地接社，额外成本主要是内容与签证模块。人民币收支对冲、航司议价等协同仍然成立。

## 5. 合规结构（技术平台版）⚠需律师出具意见

| 问题 | 风险 | 推荐结构 |
|---|---|---|
| 向中国居民销售"机+酒+车+导"打包产品是否构成组织出境游 | 可能被认定为需出境游资质的包价旅游 | **阶段 1**：中国用户的打包产品通过**持牌出境社作为合同主体**（平台提供技术与供应链，按 SaaS/技术服务收费）；平台自身只直接销售**单项组件代订**和**目的地当地产品**（由肯尼亚持牌主体提供）。**阶段 3**：视规模设立中国实体并申请资质或收购持牌社 |
| 机票出票资质 | 自行出票需 IATA/航协资质 | 使用聚合商（如 Duffel 等），由其作为出票方；或与持 BSP 资质的票代合作 |
| 肯尼亚本地服务 | 需 TRA 牌照 | 肯尼亚公司申请 TRA 牌照，作为本地产品的合同主体；平台上的车队/营地供应商须持有效牌照（入驻时校验） |
| 小程序、支付、域名 | 微信小程序与微信支付/支付宝境内收款需中国主体；境内服务器需 ICP 备案 | 早期以合作持牌社小程序/收款，或使用**跨境收单**（境外商户接入微信/支付宝跨境支付）⚠待核实；中期设立中国公司 |
| 生成式 AI 服务 | 面向中国境内公众提供生成式 AI 服务需遵守《生成式人工智能服务管理暂行办法》，涉及备案/登记、内容安全 | 中国区调用**已备案的国产大模型**（如通义千问、DeepSeek、文心等），完成大模型应用登记 ⚠待核实流程；加内容安全过滤；境外区可用国际模型 |
| 个人信息与跨境传输 | 护照号、行程属敏感个人信息；PIPL 跨境传输规则；肯尼亚 DPA 2019 | 中国用户数据存中国区（阿里云/腾讯云），仅把**下单必需字段**传至境外供应商，单独同意 + 标准合同/认证路径；肯尼亚侧向 ODPC 登记 |
| 消费者保护 | 动态打包的退改责任、价格展示 | 每个组件退改规则在付款前清晰展示；平台承担"编排失败"兜底责任 |

## 6. 竞争与壁垒

| 竞争者 | 能力 | 我们的差异 |
|---|---|---|
| 携程/飞猪等 OTA | 机酒强，已有 AI 助手 | 东非本地用车、营地、迁徙动态覆盖薄；不做深度目的地规划 |
| 通用 AI（豆包、Kimi、ChatGPT 等） | 能写行程 | 不能核价、不能预订、常给出不可执行的路线（车程/门票/营地错误） |
| 国际 Safari 平台（如 SafariBookings 等询价平台） | 欧美客源、运营商目录 | 无中文、无一键预订，多为询价撮合 |
| 华人地接社 | 线下服务 | 不透明、不可即时预订；**可作为平台供应商**而非竞争者 |

**四层壁垒**：
1. **本地供给网络**：签约并数字化的车队、营地、中文导游（平台独家或优先库存）；
2. **动态数据**：司机端回传的动物目击、路况、营地实际情况，喂给推荐算法；
3. **可执行性**：约束求解器保证行程在时间、距离、预算上可行，所有价格实时核验；
4. **双向网络**：同一套供给与支付体系服务两条客流，后续可复制到坦桑尼亚、卢旺达、乌干达。

### 7.2 资金需求
- 至盈亏平衡（约第 30 个月）累计投入约 **US$1.0–1.2M**。
- 建议分两轮：**种子轮 US$500–600k**（MVP + 首个旺季验证）→ **Pre-A US$800k–1M**（规模化获客、B 线上线、SaaS）。
- 与 V1 对比：前期亏损更大，但不需要营运资金垫付，规模上限和估值逻辑（平台/SaaS 倍数）显著更高。

## 8. 关键风险（新增于平台模式）

| 风险 | 应对 |
|---|---|
| AI 给出不可执行或错误信息（营地已满、车程错误、签证政策过期） | 大模型只负责理解与表达，路线可行性由规则与求解器校验，价格/库存只取实时接口；政策类内容有人工审核与过期时间 |
| 本地供应商数字化意愿低 | WhatsApp 确认、免费门户、先结算后收佣、更快回款作为激励 |
| 一键预订部分失败（如机票出票成功而营地满） | 先锁价/预留再统一支付，Saga 编排 + 自动替代方案 + 兜底退款，见 04 第 6 节 |
| 大模型合规（中国区） | 使用已备案国产模型、内容安全审核、日志留存 |
| 获客成本高（长尾目的地，决策周期长） | 内容驱动（小红书/抖音的 AI 生成攻略可直接"一键带走行程"），SaaS 借旅行社的存量客户 |
| 供应商 API 依赖与成本 | 多供应商抽象层，避免绑定单一聚合商 |
